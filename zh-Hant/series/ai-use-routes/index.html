用 AI 做實際工作

用 AI，不必先變成 AI Engineer

想用 AI 幫忙做事，不必先證明自己屬於哪種技術角色。不寫 Code 可以從只出草稿的流程開始；有寫 Code 可以逐項看 AI 建議的改動。最後決定仍然在人手。

兩條路線

今天想先做好哪一件事？

依工作內容選路。從一件小、低風險、做錯仍能收回的事開始。

開始前寫下四件事

  • 誰要根據這份結果決定什麼？
  • 正常、缺資料與不該做的情況，預期結果分別是什麼？
  • 這一步要開哪些權限？
  • 發送、更新、核准與部署由哪位負責的人做？
01 · 不寫 Code

我不寫 Code，但想穩健地使用 AI

把日常整理工作收窄成只出草稿的流程：輸入是什麼、結果要長什麼樣、誰會核對。AI 不會自己做下一步。

  1. 挑一個小而低風險的決定。
  2. 寫下資料欄位、預期結果與幾個例外。
  3. AI 只負責起草、分類或比較；實際行動留給人。
開始 15 分鐘手動檢查（不需登入） →想先了解原理，閱讀不寫 Code 路線 →
02 · 有寫 Code

我有寫 Code，想用 AI 一起做

你寫清楚要改什麼和怎樣才算完成；AI 只提方案、差異與測試，人工再決定用不用。

  1. 寫下功能、非目標與完成條件。
  2. 在合成或隔離環境執行測試，逐項看差異。
  3. 留下通過、要修正或停止的決定，以及退回上一版的方法。
開始 15 分鐘案例判斷（暫不寫 Code） →想先了解原理，閱讀 coding partner 路線 →

兩種開始方法

每條路先有一個短起步，再留下一份說得清楚的成果

上方每條路只會給你一個首選起步；完成後，再用下方路線內容延伸。不寫 Code 路線先幫你說清楚工作與檢查方法；要看實作、改動或測試時，再去 coder 路線。

有寫 Code 路線

從一份改動說明，做到可覆核的程式工作

已有程式碼庫，或想試 agent 提議的改動，就先說清這次要做什麼、不做什麼、怎麼測試、資料能不能用，以及出事時怎麼退回上一版。寫更多程式碼不是目標。

完成 15 分鐘起步後，再做完整程式覆核

15 分鐘只判斷 TC-01 與 TC-06，暫時不寫 Code。只有有 45–60 分鐘時，才用六份英文虛構來源檔完成改動說明、人工基準、程式差異與覆核記錄。

何時轉去寫 Code 路線？

需要看程式碼、跑測試或實作受控改動時，再轉到寫 Code 路線。一旦要求涉及真實資料、登入、連接 app、發送、更新、核准或部署，就先停止，交給有權限的人決定；寫 Code 不會讓這些 action 自動獲准。
