選 AI 課程前，先寫下這週要留下的一項可核對成果。若學習來源不能讓你留下可重跑、可說明、也能面對目標職務追問的內容，證書或工具清單都不夠。

從能力缺口開始

「想學 AI」不是一個可以比較的需求。先從一個目標工作或 project 的缺口開始，例如：我可以寫 prompt，但不能設計 evaluation；我懂 notebook，卻不能把資料、版本和 deployment 說清；我有 RAG demo，但沒有 business problem、權限邊界和 failure cases。

一篇課程清單可以幫你發現方向，但它不會證明某一門課適合你，更不會自動變成求職證據。AI.DOG 把學習來源當成手段：先決定你要留下哪一件 artefact，再判斷哪種學習形式值得投入。

不同來源真正可提供什麼

  • 官方文件、papers 和開源 README：適合補準確概念、API 邊界和可重跑最小例子。缺點是沒有節奏和 feedback；你要自己定題目與驗收。
  • 有作業的結構化課程：可以幫你排好先後、增加練習壓力，並可能提供 rubric 或同儕 feedback。它的價值取決於作業能否改成可展示 artefact，不是課名是否熱門。
  • guided build、workshop 或 cohort：適合卡在問題拆解、code review 或解釋取捨的人。確認 feedback 是針對你自己的交付，還是只有通用直播。
  • 公開資料 challenge、hackathon 或 volunteer build：可以練 collaboration 和不完整需求，但要預先確認資料、隊友貢獻和公開權利；不能把整隊成果當成自己做的。
  • 自訂 portfolio sprint：最直接補目標職務缺口。它需要你自己維持節奏，但可以把每一步都連到 README、eval report 和 interview explanation。

沒有一種來源天然較高級。若你的缺口是 evaluation，第二門 prompt course 未必比一個固定 test set 和 error analysis 更有用。

入讀前做六個檢查

1. 它補哪一個具體缺口？

寫成一句可反駁的話，例如「完成後我可以替一個合成 RAG case 寫 baseline、test set、metric definitions 和 release gate」。如果只能寫「我會更懂 GenAI」，範圍仍然太大。

2. 我會帶走什麼 artefact？

開課前先定一個可公開輸出：problem brief、data card、evaluation report、architecture note、可重跑 notebook、decision log 或一段清楚界定個人貢獻的 README。證書可以保留，但不能是唯一 artefact。

3. 是否有 feedback，而且 feedback 可用？

看作業、rubric、office hour、code review、project critique 或示範答案的邊界。若 feedback 只告訴你「完成了」，它未必能提升你對 failure mode 或取捨的理解。

4. 它怎麼驗收理解，而不只是點擊完成？

優先看能否解釋一個決定、比較 baseline、處理失敗或把方案交給別人重跑。純選擇題和跟著影片複製可以是起步，但不足以成為你唯一的證據。

5. 時間、金錢和更新負擔合理嗎？

把總成本算進去：課時、作業、工具、雲端、交通、延後投遞工作的機會成本，以及內容是否可能很快過期。高價不等於有 feedback，免費不等於沒有價值。

6. 有沒有停止條件？

例如第四週後仍未做出第一個可檢查 artefact、課程與目標職務無關、資料不能合法公開、或作業只能複製講師答案，就停止或改用較小的學習單位。停止不是失敗，是不讓 sunk cost 取代判斷。

把課程整理成八週成果計畫

第 1 週選一個角色和一個缺少證據；第 2 週寫 project brief 與 baseline；第 3 到 4 週用課程材料做最小可重跑實作；第 5 週補 evaluation cases；第 6 週記錄 failure、cost 和資料邊界；第 7 週讓一位同學或 reviewer 按 rubric 質疑；第 8 週整理 README、decision log 和五分鐘 walkthrough。

這個節奏不保證你找到工作。它只保證：若投入值得，你會拿到一份能被檢查的輸出，而不是只多一個完成紀錄。

例子：把 RAG 課程作業改成有範圍的案例

假設課程教你把文件放進 vector index。你可以把作業改成 PolicyPilot 的一個小切片：自己寫虛構政策資料、先做 keyword baseline、加不同 region 的 metadata filter、建立無答案和 injection tests，並解釋為什麼沒有讓系統退款。工具可能相同，但你新增了 business boundary、evaluation 和人工責任，因此作品才有可追問的工程判斷。

課程實際能幫到什麼

好課程可以減少你排課綱的負擔、提供 feedback、設定 deadline，也幫你接觸不會自己找的概念。它不能代替你選問題、驗收結果、處理隱私或說清自己的貢獻。把課程當成素材庫和節奏器，而不是身份標籤。
