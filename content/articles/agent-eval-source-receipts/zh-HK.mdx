唔好由「邊個 AI course 最好」開始。先講清楚你而家要補嘅 evidence gap：係未明白 agent 點樣拆 task、未識設計有狀態嘅 workflow、未留過可重跑嘅 evaluation case，定係未試過把一個 provider run 交代清楚。課程、framework 同文件只係學習輸入；你要帶走嘅係一份別人可以檢查嘅判斷。

## 五張官方 source receipt，而唔係一張課程排名表

以下係五個官方起點，於 2026-09-25 核對。它們不是 affiliate link、推薦次序、求職保證，亦不表示你要全部完成。每一張 receipt 都配一份 AI.DOG 自行設計的第一星期練習，把讀到的概念轉成你自己的、只用 synthetic 或公開安全資料的 evidence；它不搬課程作業，也不扮成 provider 認可的成果。

開始前，先揀一句最接近你的情況：

- 我想講清 agent 的 tool、觀察和 task loop，但只識背名詞。
- 我想把 route、state、memory 同 human handoff 寫成可檢查流程。
- 我想知道 runtime event、sandbox 和 cleanup 是甚麼，不想把一次「完成」誤當成功。
- 我想將「答案好似得」變成固定 cases、assertion 和 reviewer note。
- 我想練習較正式的 evaluation 方法，但未應該直接接真實資料或帳戶。

## 1．先補 agent 的共同語言：Hugging Face AI Agents Course

[Hugging Face AI Agents Course](https://huggingface.co/learn/agents-course/unit0/introduction) 將 agent fundamentals、常見 libraries、hands-on、use-case assignment、challenge 同 evaluation/observability 單元放在同一條學習線。官方列出的起點是 basic Python 同 basic LLM knowledge；要用 Hub 或 Spaces，亦要有 Hugging Face 帳戶。

它適合你想先分清 **tool、thought、action、observation** 唔係同一件事，而非立即砌一個聲稱可以自動做任何事的 agent。

**今個星期留下甚麼：** 用三份你自己寫的 synthetic FAQ 或 role card，畫一張 `input → allowed tool → observation → draft → human decision` 小圖。再寫三個 case：正常資料、缺資料、有人叫它做禁止 action。每個 case 都要有預期 route：`DRAFT`、`HANDOFF` 或 `BLOCKED`。

**你可以檢查到：** tool contract、輸入邊界、可見的 route 和一個不讓 agent 越過的人手 decision。

**完成後仍不能聲稱：** 你有 enterprise agent、framework 選得正確、所有 tool 都安全，或 challenge／certificate 等同能交付真實工作。課程完成與你的 portfolio evidence 是兩件事。

## 2．想練 state 同 human gate：LangGraph Foundation

[LangChain Academy 的 Introduction to LangGraph](https://academy.langchain.com/courses/intro-to-langgraph) 的公開課程結構涵蓋 simple graph、router、agent、state schema、memory、breakpoint、human feedback 同 deployment 概念。頁面現時列出免費、55 個 lessons、約六小時影片；它同時說明 LangGraph library 是 MIT license。呢兩件事都不代表課程文字、任何雲端服務或你接上的 model provider 可以隨便重用或免費運行。

它適合你已經懂少少 Python，想由「一個 chat loop」走去看 **state 由誰改、何時中斷、誰可以覆寫 decision**。

**今個星期留下甚麼：** 做一張小 workflow state card：`received`、`needs-evidence`、`draft-ready`、`review-required`、`stopped`。只容許一個 synthetic request 由 `draft-ready` 進 `review-required`，然後由 named reviewer 選 `PASS`、`REVISE` 或 `STOP`。保留一張 transition table 和一個被拒絕的 state transition。

**你可以檢查到：** state schema、每一條 transition 的 owner、interrupt 點和一份 failure record。

**完成後仍不能聲稱：** 你有 production orchestration、long-term memory 已可靠、deployment 已完成，或 human-in-the-loop 只要加一個按鈕便足夠。真正資料權利、成本、permission 同 incident path 仍要另外設計。

## 3．想看 managed runtime 的證據：OpenAI Agents API quickstart

[OpenAI Agents API quickstart](https://developers.openai.com/api/docs/guides/agents-api/quickstart) 用 hosted sandbox 示範建立 session、執行工作、stream event 和 cleanup。官方把 API key、指定 permission scopes 和 beta header 列為 prerequisite，並特別提醒：一個 completed turn 不代表每個 tool 都成功。

這條路只適合你已經有程式基礎、亦有明確的 API／支出／資料授權。對第一個 portfolio 練習而言，**不需要 key** 才可以先學到最重要的判斷。

**今個星期留下甚麼：** 不作 live call。用一份英文 `session-receipt.md` 寫一個虛構、local-only task 的 expected events：`started`、`tool-requested`、`tool-result`、`completed`／`failed`／`cancelled`。指定甚麼 event 仍要 human review、何時 cleanup、以及缺少哪個 result 就不得說成功。這是一份 static fixture design，不是 API output。

**你可以檢查到：** session boundary、event interpretation、success 與 completion 的分別、cleanup owner 和 credential boundary。

**完成後仍不能聲稱：** 你已跑過 OpenAI API、model output 已被觀察、sandbox 配置安全、成本可控或 workflow 能用於真實帳戶。要跑真實實驗，是另一份授權、測試集、成本、logging 和 release evidence。

## 4．想把「睇落 OK」變成 case matrix：Promptfoo

[Promptfoo Getting Started](https://www.promptfoo.dev/docs/getting-started/) 展示 `promptfooconfig.yaml` 如何放 prompt、provider 和 test case，也支援 assertions、跑 evaluation 同檢視輸出。官方同時說明很多 provider 要 authentication；不要因為你有一份 YAML，就把 credential、客戶資料或真實 prompt 帶進公開 repository。

它適合你已有 Node／CLI 基礎，想補的是 **evaluation evidence**，而不是另一個漂亮 demo。

**今個星期留下甚麼：** 建一份 key-free、fixture-only `promptfooconfig.yaml` 草案，只有五個 synthetic cases：正常 request、缺 source、矛盾 source、hidden instruction、禁止 action。每個 case 寫 expected route、可見 evidence 和 `PASS`／`REVISE` rule。第一次可以只做 manual review；不要把未跑過的 provider 寫成 test result。

**你可以檢查到：** case set、expected assertion、failure taxonomy、一次 reviewer decision，以及 prompt 改前改後怎樣比較。

**完成後仍不能聲稱：** 本地 pass rate 等於真實流量品質、business KPI、privacy review、agent trajectory safety 或 production approval。Promptfoo 是一個 eval harness；它不能替你定義資料權利和 action boundary。

## 5．想學 cloud evaluation 的方法，而唔係只比較 model：Microsoft Learn

[Microsoft Learn 的 Evaluate generative AI applications](https://learn.microsoft.com/en-us/training/paths/evaluate-generative-ai-apps/) 包括 evaluation fundamentals，以及用 Azure AI Evaluation SDK 跑 evaluation 和生成 synthetic dataset。它列出的前置包括 Azure subscription、Azure portal 熟悉度、初階 Python；browser 或 local development 亦有 GitHub、Docker、VS Code／Dev Containers 等要求。頁面提到 free account／trial 與 pay-as-you-go，唔可以將它簡化成「一定零成本」。

它適合你想練 **evaluation plan、quality/risk metric、synthetic test data**，而不是只問哪個 model 較好。

**今個星期留下甚麼：** 做一張一頁 evaluation plan：虛構 user decision、五個 synthetic cases、一個 quality metric、一個 risk metric、誰讀結果、甚麼 outcome 必須 STOP。就算你暫未有 Azure account，也可以先完成這份 plan；它令你日後不會由「先開服務」代替「先定義要驗收甚麼」。

**你可以檢查到：** evaluator 的問題、metric 與 failure mode 的關係、synthetic data boundary、result interpretation 和 human release decision。

**完成後仍不能聲稱：** 已驗證其他 provider、真實資料分布、成本、合規或機構批准。一條 cloud learning path 不是 production evidence。

## 用同一張 receipt，選一條而唔係累積五個 badge

每次準備開始新的來源，留一張英文 source receipt。程式、fixture、config 和 file name 保持英文，方便 reviewer 重跑；README 可按讀者需要提供不同語言。

```text
Source title and official URL:
Accessed on:
Evidence gap I am addressing:
Prerequisites and account/cost boundary I checked:
One lesson or section I used:
My independently authored Week-1 artefact:
Synthetic/public data boundary:
Five fixed cases or checks:
Feedback or review route:
What failed, remains unknown, or must stop:
What this artefact does not prove:
```

呢張 receipt 將「我睇過某個 course」變成「我如何把一個來源轉成可重看的 engineering decision」。它亦保護你不會把 instructor solution、course wording 或 certificate，假裝成完全原創的 commercial work。

## 一個簡單選擇規則

如果你未能講清 agent 的組成，先選 Hugging Face 的 fundamentals；如果問題是 state、handoff 或 interrupt，就看 LangGraph；如果你要理解 hosted session/event 的真正邊界，先讀 OpenAI quickstart 但不要急於加 key；如果需要固定 test cases 和 regression evidence，先做 Promptfoo 的 fixture-only pack；如果你要建立 evaluation methodology，再考慮 Microsoft Learn。

無論選哪一條，第一星期只做一份可檢查 artefact。當你仍未能寫 expected result、需要真實私人資料、要接帳戶、要花錢、要發送資料，或者沒有人肯擁有最終 decision，就先 STOP。收窄 task 比加另一個 framework 更有價值。

已有一個具名來源想核對？先用[學習證據規劃器](/zh-HK/learning-evidence-planner)記低缺口、官方頁、第一份成果同停止條件；它唔會替供應者排位。
