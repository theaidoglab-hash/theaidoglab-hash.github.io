不要从“哪门 AI 课程最好”开始。先说清楚你现在要补的 evidence gap：还不能解释 agent 如何拆 task、还没有把 workflow state 和人工交接写清楚、还没留下可重跑的 evaluation case，还是看不懂 runtime event。课程、framework 和文档只是学习输入；真正要留下的是别人能检查的判断。

## 五张官方 source receipt，而不是课程排名表

以下五个官方起点于 2026-09-25 核对。它们不是 affiliate link、推荐顺序、求职保证，也不表示你必须全部完成。每张 receipt 都配一份 AI.DOG 自行设计的第一周练习：不抄课程作业、不假装是 provider 认可成果，而是把读到的概念转成你自己的、只使用 synthetic 或公开安全资料的 evidence。

先选一句最像你当前状态的话：

- 我想理解 agent 的 tool、observation 和 task loop，不想只会背术语。
- 我需要让 route、state、memory 和 human handoff 可被检查。
- 我想弄懂 runtime event、sandbox 和 cleanup，不把“completed”当作成功。
- 我想把“看起来可以”变成固定 cases、assertion 和 reviewer note。
- 我想练较正式的 evaluation 方法，但还不应该接入真实资料或账户。

## 1．先补 agent 的共同语言：Hugging Face AI Agents Course

[Hugging Face AI Agents Course](https://huggingface.co/learn/agents-course/unit0/introduction) 把 agent fundamentals、常见 libraries、hands-on、use-case assignment、challenge 和 evaluation/observability 单元放在同一条学习线。官方列出的起点是 basic Python 和 basic LLM knowledge；若要使用 Hub 或 Spaces，也需要 Hugging Face 账户。

它适合你想先分清 **tool、thought、action、observation** 不是同一件事，而不是马上做一个声称能自动处理所有事情的 agent。

**第一周留下什么：** 用三份自己写的 synthetic FAQ 或 role card，画一张 `input → allowed tool → observation → draft → human decision` 小图。再写三个 case：正常资料、资料缺失、有人要求禁止 action。每个 case 都要有预期 route：`DRAFT`、`HANDOFF` 或 `BLOCKED`。

**别人能检查什么：** tool contract、输入边界、可见 route，以及 agent 无法越过的人工决策。

**完成后仍不能宣称什么：** 你已有 enterprise agent、选对 framework、每个 tool 都安全，或 challenge／certificate 等于能交付真实工作。完成课程与建立 portfolio evidence 是两回事。

## 2．想练 state 与人工关卡：LangGraph Foundation

[LangChain Academy 的 Introduction to LangGraph](https://academy.langchain.com/courses/intro-to-langgraph) 公开课纲包括 simple graph、router、agent、state schema、memory、breakpoint、human feedback 和 deployment 概念。页面目前列出免费、55 个 lessons、约六小时影片，并说明 LangGraph library 是 MIT license。这两件事都不代表课程文字、任何云端服务或你接上的 model provider 可以任意重用或免费运行。

它适合你已有一些 Python 基础，想从“一个 chat loop”走到看清 **谁可以改 state、何时暂停、谁能覆写 decision**。

**第一周留下什么：** 做一张 workflow state card：`received`、`needs-evidence`、`draft-ready`、`review-required`、`stopped`。只允许一个 synthetic request 从 `draft-ready` 走到 `review-required`，再由 named reviewer 选 `PASS`、`REVISE` 或 `STOP`。保留 transition table 和一个被拒绝的 transition。

**别人能检查什么：** state schema、每一条 transition 的 owner、interrupt 点和 failure record。

**完成后仍不能宣称什么：** 你有 production orchestration、long-term memory 已可靠、deployment 已完成，或加上 human-in-the-loop 按钮就解决 permission、资料权利、成本和 incident path。

## 3．想看 managed runtime 的证据：OpenAI Agents API quickstart

[OpenAI Agents API quickstart](https://developers.openai.com/api/docs/guides/agents-api/quickstart) 用 hosted sandbox 示范建立 session、执行工作、stream event 和 cleanup。官方把 API key、指定 permission scopes 与 beta header 列为 prerequisite，也特别提醒：completed turn 不表示每个 tool 都成功。

这条路只适合已有编程基础，也有明确 API／支出／资料授权的人。做第一个 portfolio 练习时，**不需要 key** 才能先学到最重要的判断。

**第一周留下什么：** 不做 live call。用英文 `session-receipt.md` 写一个虚构、local-only task 的 expected events：`started`、`tool-requested`、`tool-result`、`completed`／`failed`／`cancelled`。指定哪些 event 仍要 human review、何时 cleanup，以及少了哪个 result 就不能宣称成功。这是 static fixture design，不是 API output。

**别人能检查什么：** session boundary、event interpretation、completion 与 success 的差异、cleanup owner 和 credential boundary。

**完成后仍不能宣称什么：** 你已跑过 OpenAI API、观察过 model result、配置了安全 sandbox、控制了成本，或能把 workflow 用于真实账户。live experiment 需要另一份资料授权、test set、成本控制、logging 和 release evidence。

## 4．把“看起来 OK”变成 case matrix：Promptfoo

[Promptfoo Getting Started](https://www.promptfoo.dev/docs/getting-started/) 示范 `promptfooconfig.yaml` 如何放入 prompt、provider 与 test case，也支持 assertions、执行 evaluation 和检视 outputs。官方也说明许多 provider 需要 authentication；有一份 YAML 不表示你可以把 credential、客户资料或真实 prompt 放进公开 repository。

它适合你有基本 Node／CLI 概念，现在缺的是 **evaluation evidence**，不是另一个漂亮 demo。

**第一周留下什么：** 建一份 key-free、fixture-only 的 `promptfooconfig.yaml` 草案，只有五个 synthetic cases：正常 request、缺 source、矛盾 source、hidden instruction、禁止 action。每个 case 写 expected route、可见 evidence 和 `PASS`／`REVISE` rule。第一次可以先 manual review；不要把还没跑过的 provider 写成 test result。

**别人能检查什么：** case set、expected assertion、failure taxonomy、一次 reviewer decision，以及 prompt 改前改后如何比较。

**完成后仍不能宣称什么：** 本机 pass rate 等于真实流量品质、business KPI、privacy review、agent trajectory safety 或 production approval。Promptfoo 是 eval harness；它不能替你定义资料权利和 action boundary。

## 5．学 cloud evaluation 的方法，不只比 model：Microsoft Learn

[Microsoft Learn 的 Evaluate generative AI applications](https://learn.microsoft.com/en-us/training/paths/evaluate-generative-ai-apps/) 包括 evaluation fundamentals，以及用 Azure AI Evaluation SDK 跑 evaluation 和生成 synthetic dataset。列出的先备包括 Azure subscription、Azure portal 熟悉度、初阶 Python；browser 或 local development 还有 GitHub、Docker、VS Code／Dev Containers 等要求。页面提到 free account／trial 和 pay-as-you-go，不能直接说成“一定零成本”。

它适合你想练 **evaluation plan、quality/risk metric、synthetic test data**，而不只是问哪个 model 较好。

**第一周留下什么：** 做一张一页 evaluation plan：虚构 user decision、五个 synthetic cases、一个 quality metric、一个 risk metric、谁阅读结果，以及什么 outcome 必须 `STOP`。你可以在还没开 Azure account 前先完成这份 plan；它让“定义如何验收”先于“开启服务”。

**别人能检查什么：** evaluator 的问题、metric 与 failure mode 的关系、synthetic data boundary、result interpretation 和 human release decision。

**完成后仍不能宣称什么：** 已验证其他 provider、真实资料分布、成本、合规或组织批准。cloud learning path 不是 production evidence。

## 用同一张 receipt，选一条而不是收集五个 badge

每次开始新来源时，都保留一张英文 source receipt。程序、fixture、config 和 file name 保持英文，让 reviewer 能重跑；README 再按读者需要做不同语言版本。

```text
Source title and official URL:
Accessed on:
Evidence gap I am addressing:
Prerequisites and account/cost boundary I checked:
One lesson or section I used:
My independently authored Week-1 artefact:
Synthetic/public data boundary:
Five fixed cases or checks:
Feedback or review route:
What failed, remains unknown, or must stop:
What this artefact does not prove:
```

这张 receipt 把“我看过某个 course”变成“我如何把一个来源转成可 review 的 engineering decision”。它也保护你不会把 instructor solution、course wording 或 certificate，假装成完全原创的 commercial work。

## 一个简单的选择规则

如果你还不能解释 agent 的组成，先从 Hugging Face fundamentals 开始；问题是 state、handoff 或 interrupt 时，看 LangGraph；想理解 hosted session/event 的真正边界，就读 OpenAI quickstart，但不要急着加 key；需要固定 case 和 regression evidence，就先做 Promptfoo fixture-only pack；想补 evaluation methodology，再考虑 Microsoft Learn。

不论选哪条路，第一周只做一份可检查 artefact。当你无法写 expected result、需要真实私人资料、需要连账户、需要花钱、需要向外发送资料，或没有人愿意拥有最后 decision 时，就先 STOP。缩小 task 比多加一个 framework 更有价值。
