# Threat model — PolicyPilot

**狀態：僅限內部草稿｜本文件是設計練習，不是安全認證。**

## 系統邊界

輸入是合成問題；知識庫是已批准的合成政策；輸出只可以是帶引用的草稿、澄清問題或交接建議。系統沒有帳戶、支付、訂單、外發訊息或寫入工具。

## 保護的東西

- 政策版本的完整性與可追溯性；
- 合成測試資料不被混入真實個資；
- 人手對最終回覆和所有外部行動的控制權；
- traces 中不包含秘密、真實帳戶或敏感 prompt。

## 威脅與控制

| 威脅 | 例子 | 預防控制 | 偵測／處置 |
| --- | --- | --- | --- |
| Prompt injection | 使用者要求忽略政策 | 固定 system boundary；不把使用者文字寫入知識庫 | 標記 injection，交接，保留最少 trace |
| 文件漂移 | 舊政策仍被引用 | 狀態與有效日期 filter；版本化 corpus | 每次輸出記錄 policy version；可撤回版本 |
| 無根據答案 | 模型補上例外條件 | 引用必需；無足夠來源即交接 | citation audit；將失敗加回測試集 |
| 越權行動 | 請模型退款、改單或發送 | 不連接寫入工具；action allowlist 為空 | 拒絕／交接；測試中驗證零 action |
| 個資混入 | 測試 prompt 有真實電郵 | 合成資料規則、輸入提醒、最少留存 | 停止測試、移除資料、記錄事件 |
| 成本／可用性失控 | 長 prompt 或重試循環 | 輸入長度、重試和成本上限 | timeout／budget alert，回退至人手 |

## 殘餘風險與停止條件

即使沒有外部工具，錯誤草稿仍可能誤導人。因此任何無法引用、無法辨識來源版本、或多次錯誤 route 的情況，都應停止 demo、回到資料與測試設計。這個 prototype 永遠不能用「模型看起來合理」取代人手批准。
