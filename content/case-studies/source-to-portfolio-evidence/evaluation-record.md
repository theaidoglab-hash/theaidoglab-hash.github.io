# 評估紀錄（Evaluation record）

**狀態：`僅限內部草稿`**
**作品 ID：** `[填寫]`
**評估版本：** `[eval-v1]`
**資料版本：** `[synthetic-v1／authorised-v1]`

> 這不是 model leaderboard。它記錄一個受限 prototype 是否能在固定 case 下協助某個清楚的人手決定；任何「改善」都只限於這個資料、環境和版本。

## 1. 評估合約

| 問題 | 填寫內容 |
| --- | --- |
| 被評估的決定 | `[例如：產生可覆核草稿／交給人手／拒絕處理]` |
| 成功的最低條件 | `[例如：正確顯示來源、沒有越權行動、需要時交接]` |
| 操作／產品 proxy | `[例如：reviewer 可用率、交接完整度、處理一致性]` |
| 模型或系統品質指標 | `[例如：case pass rate、引用完整度、拒絕／交接正確率]` |
| 風險 guardrail | `[例如：0 次外發、0 次帳戶修改、敏感輸入必須 blocked]` |
| 不在評估範圍 | `[真實 ROI、用戶滿意度、產量、production latency、其他]` |

至少保留一項操作／產品 proxy 和一項系統品質指標；不要只以模型指標取代真正想改善的決定。

## 2. 資料與固定 case 集

| 欄位 | 填寫內容 |
| --- | --- |
| 資料權利 | `完全合成／公開且條款允許／明確書面授權` |
| 禁止資料 | `僱主、客戶、同事、真實帳戶、未公開文件、個人資料` |
| case 集凍結日期 | `[YYYY-MM-DD]` |
| case 集位置和 checksum／版本 | `[本地路徑及版本]` |
| case 數量與類別 | `[正常／無答案／矛盾／越權／injection／其他]` |
| 誰可改 expected result | `[負責人或指定 reviewer；改動要建新版本]` |

固定 case 不等於永遠不變；它表示同一輪比較中不會因為輸出不好看而改動。新增 case 要建立 `eval-v2`，保留 `eval-v1` 的結果和原因。


「本機跑過」不是可重現。只有當另一個乾淨環境按這些資料能得到同類型的結果，才寫作「已重現本地結果」；即使如此，它仍不是 production 驗證。
