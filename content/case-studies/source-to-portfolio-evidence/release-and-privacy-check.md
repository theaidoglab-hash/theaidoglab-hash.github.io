# 公開與私隱檢查（Release and privacy check）

**狀態：`僅限內部草稿`**
**作品 ID：** `[填寫]`
**擬定處理：** `只留本地／待負責人審閱／停止`

完成本清單不會自動授權發佈、部署、收費、收集資料、建立帳戶或聯絡任何人。任何外部動作仍需要負責人的明確批准，以及必要的權利、僱傭、私隱和平台確認。

## 1. 資料與私隱

- [ ] 所有資料均為完全合成、公開且條款允許，或有可保存的明確授權。
- [ ] 沒有僱主、客戶、同事、使用者、供應商或合作方的名稱、截圖、系統畫面、資料、帳戶或內部流程。
- [ ] 沒有個人資料、私密提示詞、API key、token、cookie、log、真實對話或可重新識別的組合線索。
- [ ] 已說明資料的版本、來源、可見範圍和刪除／保留方式。
- [ ] 任何 example 都是完全虛構，並非把真實案例換名。

## 2. 來源與知識產權

- [ ] `source-receipt.md` 列明 URL、版本／日期、存取日期、授權／條款和重用邊界。
- [ ] 已分開標示直接複製、摘要、改寫和自行新增；沒有把別人的文字、程式、資料或圖表冒認為自己的。
- [ ] 無法確認重用權的材料已移除，或只留下自行撰寫的抽象概念。
- [ ] 沒有使用來源的 logo、商標、學員評價、成效數字或暗示合作／認可的措辭。
- [ ] 不把來源提供者、課程或平台寫成建議、推薦、認證或職涯保證。

## 3. 技術與主張邊界

- [ ] 有 baseline、固定 evaluation version、case 級結果和至少一項 failure／未知。
- [ ] 有可重跑的本地環境、指令、輸入版本和輸出位置；重現範圍不需私密帳戶或真實資料。
- [ ] 明確寫出 prototype 的禁止動作及 human handoff／blocked 路徑。
- [ ] 沒有聲稱 production-ready、enterprise-grade、安全認證、合規、ROI、節省成本、職位保證或已部署。
- [ ] 不把本地 test pass 說成外部發布、真實使用者驗證或商業成果。

| 決定 | 只能由誰作出 | 所需證據 | 目前狀態 |
| --- | --- | --- | --- |
| 保留為本地練習 | 作者／負責人 | 本清單和本地紀錄 | `[填寫]` |
| 以草稿方式內部審閱 | 負責人 | 來源、私隱、主張、評估紀錄 | `[填寫]` |
| 對外公開文字或 repository | 負責人明確批准 | 上述全項；另行確認授權、僱傭／IP、私隱及平台規則 | `[填寫]` |
| 收費、訂閱、捐款、帳戶或資料收集 | 負責人明確批准及所需合法安排 | 付款、稅務、退款、私隱和資料處理決定 | `[填寫]` |

外部公開、部署、收費或資料連接未有明確批准及 readback 前，一律不是已完成動作。

## 5. Stop / hold 條件

請把狀態改為 `受阻`，而不是勉強刪幾句後公開，若：

- 不能證明資料或來源的重用權；
- 需要使用真實公司／客戶資料才可讓作品看起來有說服力；
- 任何內容可能拼湊出身份、僱主、客戶或內部系統；
- 作品的評估、failure 或重現步驟缺失；
- 想用「完成課程」取代實際證據，或把本地 demo 寫成職涯承諾；
- 公開或收費的權限尚未由負責人明確決定。
