# 五分鐘作品答辯（Five-minute defence）

**狀態：`僅限內部草稿`**
**作品 ID：** `[填寫]`

這不是背誦稿，也不是 pitch。它是一次自我檢查：你能否誠實地交代來源、判斷、評估和限制，而不是只展示一個流暢畫面。

## 五分鐘結構

| 時間 | 你要說清楚的事 | 不能省略的證據 |
| --- | --- | --- |
| 0:00–0:40 | 問題和使用者要作的受限決定 | `[problem brief]`；說明這是合成／已授權情境 |
| 0:40–1:10 | 來源如何啟發你，以及你沒有複製甚麼 | `[source receipt]`；URL、版本、條款狀態和改動邊界 |
| 1:10–2:00 | 系統最小設計：輸入、輸出、禁止動作、人手交接 | `[design／action contract]` |
| 2:00–2:55 | baseline 和固定 evaluation cases | `[evaluation record]`；不要只播成功 demo |
| 2:55–3:40 | 一個失敗 case：看到甚麼、風險、目前怎樣處理 | `[failure record]` |
| 3:40–4:25 | 你作過的一個重要取捨與替代方案 | `[decision log]` |
| 4:25–5:00 | 如何本地重現，以及下一個未完成的驗證 | `[command／environment／limits]` |

## 可填寫答辯骨架

```text
我做的是一個受限的 [問題] 練習。它協助 [使用者] 在 [合成／已授權] 資料中，
決定 [人手決定]；它不會 [禁止動作]。

我由 [來源 ID] 學到的是 [抽象概念]。我已記錄 URL、版本、存取日期和重用邊界；
我沒有複製 [文字／程式／資料／圖片]，而是自行完成 [問題、資料、設計、測試]。

最簡單 baseline 是 [方法]。我用凍結在 [版本] 的 [case 數量／類別] 做比較，
候選流程在 [具體範圍] 顯示 [只限本地評估的結果]。

一個重要失敗是 [case]：它 [實際行為]，因此我現在 [blocked／handoff／修正]，
而不是假裝模型總能答對。

我選擇 [設計決定]，而非 [替代方案]，因為 [可驗收取捨]。任何人可以用
[環境／command] 在沒有私密帳戶或真實資料下重跑這個範圍。下一步仍要驗證的是 [未知]。
```

## 預演追問

| 追問 | 可被支持的回答應包含 | 不應回答成 |
| --- | --- | --- |
| 這份教學來源貢獻了甚麼？ | 概念、URL、版本、條款和你自己的改動 | 「來源作者幫我設計了系統」 |
| 有甚麼是直接複製？ | 如實列出，或說明沒有；指向收據 | 「我換了變數名，所以是原創」 |
| 為甚麼先做 baseline？ | 比較點、可解釋性、失敗邊界 | 「模型看起來較聰明」 |
| case 集怎樣固定？ | 版本、資料權利、expected result 控制 | 「不通過就改答案」 |
| 最重要的 failure 是甚麼？ | Case ID、風險、處理、未知 | 「目前沒有 failure」 |
| 可否用真實公司資料再跑？ | 需要另外確認資料權利、權限和審批 | 「可以，資料放進去便行」 |
| 這是否 production-ready？ | 不是；只證明本地受限評估範圍 | 「測試過幾次，所以可以」 |
| 這能否證明你已可勝任某職位？ | 只展示某些可追問的工作方式 | 「一個 portfolio 就足夠證明」 |

答不出一題不是失敗；它通常指出下一項應補的證據或應縮小的主張。
