# 讀者體驗優化計劃

狀態：`僅限內部草稿`

日期：2026-09-27

範圍：本地 `public-site`。這份計劃只處理讀者如何找到、理解及完成一個學習步驟；不代表已部署、已發佈、已量度真實學習成效，亦不改變匿名、私隱及不保證結果的界線。

## 這一輪的判斷

網站已有針對「由哪裡開始」的診斷、路線、學習約定和完成證據。最大的可用性缺口是：帶著一條技術問題而來的讀者，例如想理解 TTFT、KV cache、context 或輸出速度，原本只能進入廣泛的資源庫或完整 roadmap。

因此這一輪採用兩個原則：

1. 先讓讀者按問題選一個窄入口，再展示完整目錄或篩選器。
2. 每個技術入口說清楚下一步、可核對的範圍，以及它不是甚麼：不是 GPU 選購、容量承諾或 production benchmark。

## 已在本地落實

- 首頁新增 LLM 系統概念小路線：四個問題分別帶到 request path、memory 壓力、context／output 取捨，以及第 03 站開始的連續心智地圖。
- 三題診斷的「概念缺口」會在有一小段可用時間的情況下，優先帶讀者到該小路線；15 分鐘情況仍保持資源庫的較短探索入口。
- 資源庫先顯示按問題選指南的路線，再顯示篩選器；新增一個 LLM 系統概念入口。這保留熟手讀者的篩選工具，同時避免第一次到訪者先面對六個控制項。
- 首頁及文章頁縮短首屏的空白與超大標題佔用，讓讀者更早看見下一步和內容目的，而不改變既有的字體、顏色或互動模式。

## 寫作與互動準則

每一份新技術學習材料優先使用以下次序：具體問題 → 一句可檢查的判斷 → 最小情境 → 機制與取捨 → 可改變的一項條件 → 下一個 measurement／檢查 → 完成條件與邊界。互動只在它能幫助讀者看到因果時使用；不以動畫或模擬數字取代證據。

## 驗收與證據界線

- 本地驗收：新手可在 60 秒內選一個入口；直接到訪技術頁的讀者可說出適合問題、下一步及非聲稱邊界；desktop、390px、鍵盤與 hash link 均沒有阻礙。
- 真實成效仍未驗證：任何招募、記錄或保存 learner session，必須先取得負責人對同意、資料位置與刪除日期的明確批准。
- 本地建置與 fixture 檢查只證明程式、路線及內容 contract；不證明學習成果、作品品質、招聘結果或 production reliability。
