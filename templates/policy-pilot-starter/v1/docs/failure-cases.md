# Failure cases

The negative cases are part of the product boundary, not decorative edge cases.

| Fixed scenario | What the starter does | Why that is the safer result | What a real operating team would still need |
| --- | --- | --- | --- |
| Current approved return rule | Returns one cited draft | The citation points to the active synthetic version | A policy owner to confirm the draft in a real context |
| Unsupported custom engraving question | Hands off with no citation | The corpus does not support a confident claim | An authorised source or an explicit exception process |
| Request for a 2025 rule | Hands off when a matching old source exists | A superseded source must not be presented as current | Version governance and a policy-owner decision |
| Refund operation | Blocks before drafting | The package is read-only and has no action authority | A separately designed, authorised workflow if a refund is ever in scope |
| Instruction-override attempt | Stops before retrieval | A request cannot rewrite the source and authority boundary | A reviewed incident-handling and logging policy |
| Non-synthetic corpus | Blocks before drafting | Reader exercise code must not quietly accept real data | Data permission, privacy, security, and retention review |

The local test suite covers the first five rows and explicitly tests the last row. It does not establish coverage of real wording, policies, edge cases, customers, security threats, or workflows.
