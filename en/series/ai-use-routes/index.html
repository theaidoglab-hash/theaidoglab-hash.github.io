Use AI for real work

Use AI without becoming an AI engineer first

You can use AI for work without first proving a technical identity. A no-code route starts with a draft-only task; a coding route lets you inspect an AI-suggested change. A person still makes the final call.

Two tracks

What do you want to make safer today?

Choose by the work in front of you. Start with something small, low-risk, and recoverable if it goes wrong.

Write down four things first

  • Who will make which decision from this result?
  • What should happen in a normal case, a missing-data case, and a request that must stop?
  • Which permissions does this step actually need?
  • Who is responsible for sending, updating, approving, or deploying?
01 · No-code route

I do not write code, but I want to use AI safely

Make a routine task draft-only: say what comes in, what should come out, and who checks it. AI does not take the next action on its own.

  1. Pick one small, low-risk decision.
  2. Write the data fields, expected result, and a few exceptions.
  3. Keep AI to drafting, classification, or comparison; leave real action to a person.

02 · Coder route

I write code and want AI alongside me

You define the change and what counts as done. The agent proposes a plan, diff, and tests; a person decides whether to use them.

  1. Write the feature, non-goal, and done condition.
  2. Run tests in a synthetic or isolated environment and inspect each change.
  3. Record pass, revise, or stop, plus how to return to the earlier version.

Two ways to begin

Each route has one short start, then something you can explain

Each route above gives you one preferred start; use the route material below only after it. The no-code route helps you define the work and how to check it; move to the coder route when you need to inspect implementation, a change, or tests.

Use Codex, Grok, or another agent for preparation work—but before anything leaves your desk, know what it read, what it did, and who makes the final call.

Coder route

Turn a change request into reviewable engineering work

If you have a codebase or want to try an agent’s change, define what this change does and does not do, how it will be tested, whether the data is allowed, and how to return to the previous version if it goes wrong. More code is not the goal.

Complete the full coding review after the 15-minute start

The 15-minute start judges TC-01 and TC-06 only; you do not write code yet. Use the six English fictional source assets for the change brief, manual baseline, diff, and reviewer record only when you have 45–60 minutes.

When should you cross over?

Move to the coder route when you need to review code, run tests, or implement a controlled change. If a request needs real data, sign-in, an app connection, sending, updating, approval, or deployment, stop and ask an authorised person to decide; writing code does not approve the action.
