选 AI 课程前，先写下这周要留下的一项可核对成果。若学习来源不能让你留下可重跑、可说明、也能面对目标职位追问的内容，证书或工具清单都不够。

从能力缺口开始

“想学 AI”不是一个可以比较的需求。先从一个目标工作或 project 的缺口开始，例如：我可以写 prompt，但不能设计 evaluation；我懂 notebook，却不能把数据、版本和 deployment 说清；我有 RAG demo，但没有 business problem、权限边界和 failure cases。

一篇课程清单可以帮你发现方向，但它不会证明某一门课适合你，更不会自动变成求职证据。AI.DOG 把学习来源当成手段：先决定你要留下哪一件 artefact，再判断哪种学习形式值得投入。

不同来源真正可提供什么

  • 官方文档、papers 和开源 README：适合补准确概念、API 边界和可重跑最小例子。缺点是没有节奏和 feedback；你要自己定题目与验收。
  • 有作业的结构化课程：可以帮你排好先后、增加练习压力，并可能提供 rubric 或同侪 feedback。它的价值取决于作业能否改成可展示 artefact，不是课程名称是否热门。
  • guided build、workshop 或 cohort：适合卡在问题拆解、code review 或解释取舍的人。确认 feedback 是针对你自己的交付，还是只有通用直播。
  • 公开数据 challenge、hackathon 或 volunteer build：可以练 collaboration 和不完整需求，但要预先确认数据、队友贡献和公开权利；不能把整个团队成果当成自己做的。
  • 自订 portfolio sprint：最直接补目标职位缺口。它需要你自己维持节奏，但可以把每一步都连到 README、eval report 和 interview explanation。

没有一种来源天然更高级。若你的缺口是 evaluation，第二门 prompt course 未必比一个固定 test set 和 error analysis 更有用。

入读前做六个检查

1. 它补哪一个具体缺口？

写成一句可反驳的话，例如“完成后我可以为一个合成 RAG case 写 baseline、test set、metric definitions 和 release gate”。如果只能写“我会更懂 GenAI”，范围仍然太大。

2. 我会带走什么 artefact？

开课前先定一个可公开输出：problem brief、data card、evaluation report、architecture note、可重跑 notebook、decision log 或一段清楚界定个人贡献的 README。证书可以保留，但不能是唯一 artefact。

3. 是否有 feedback，而且 feedback 可用？

看作业、rubric、office hour、code review、project critique 或示范答案的边界。若 feedback 只告诉你“完成了”，它未必能提升你对 failure mode 或取舍的理解。

4. 它怎么验收理解，而不只是点击完成？

优先看能否解释一个决定、比较 baseline、处理失败或把方案交给别人重跑。纯选择题和跟着影片复制可以是起步，但不足以成为你唯一的证据。

5. 时间、金钱和更新负担合理吗？

把总成本算进去：课时、作业、工具、云端、交通、延后投递工作的机会成本，以及内容是否可能很快过期。高价不等于有 feedback，免费不等于没有价值。

6. 有没有停止条件？

例如第四周后仍未做出第一个可检查 artefact、课程与目标职位无关、数据不能合法公开、或作业只能复制讲师答案，就停止或改用较小的学习单位。停止不是失败，是不让 sunk cost 取代判断。

把课程整理成八周成果计划

第 1 周选一个角色和一个欠缺证据；第 2 周写 project brief 与 baseline；第 3 到 4 周用课程材料做最小可重跑实现；第 5 周补 evaluation cases；第 6 周记录 failure、cost 和数据边界；第 7 周让一位同学或 reviewer 按 rubric 质疑；第 8 周整理 README、decision log 和五分钟 walkthrough。

这个节奏不保证你找到工作。它只保证：若投入值得，你会拿到一份能被检查的输出，而不是只多一个完成记录。

例子：把 RAG 课程作业改成有范围的案例

假设课程教你把文档放进 vector index。你可以把作业改成 PolicyPilot 的一个小切片：自己写虚构政策数据、先做 keyword baseline、加不同 region 的 metadata filter、建立无答案和 injection tests，并解释为什么没有让系统退款。工具可能相同，但你新增了 business boundary、evaluation 和人工责任，因此作品才有可追问的工程判断。

课程实际能帮到什么

好课程可以减少你排课纲的负担、提供 feedback、设定 deadline，也帮你接触不会自己找的概念。它不能代替你选问题、验收结果、处理隐私或说清自己的贡献。把课程当成素材库和节奏器，而不是身份标签。

延伸阅读：比较 AI 课程、hackathon 和活动的 scorecard、从 PolicyPilot 学习完整 portfolio evidence、按工作产出选 AI Engineering 路线。
