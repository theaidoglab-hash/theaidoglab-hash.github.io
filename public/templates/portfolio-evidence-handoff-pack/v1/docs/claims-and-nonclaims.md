# Claims and non-claims

| No project-specific claim recorded. | Not recorded | NOT_RECORDED | No claim should be made yet. | Local template only |

Only add a statement when a reviewer can find the supporting receipt or record. A screenshot, a code file, or a polished answer is not automatically evidence of a result.

## Claims this pack can support after completion

- A named local boundary and a human review point were documented.
- A listed source or fixture was recorded with its stated provenance boundary.
- A specific local run happened if the run receipt records it.
- A fixed check, failure case, or hold condition was observed if the receipt preserves it.

Each statement remains limited to the artifact actually recorded. For example, a local fixture result does not support a claim about real customers, employers, users, data, or operations.

## Non-claims to keep explicit

- The project is not a live service merely because it has a user interface or source code.
- A local pass does not prove business impact, user adoption, security approval, data rights, or reliability under real load.
- A model metric does not by itself show that a business decision improved.
- A repository candidate is not an approved public repository.
- A reviewer checklist is not a licence, legal opinion, deployment approval, or production-readiness assessment.

## Wording check before sharing

1. Can a reviewer locate the exact receipt behind this sentence?
2. Does the sentence name the local, fixture, public, licensed, or owner-provided boundary?
3. Does it avoid implying a real-world result that was not measured?
4. Does it preserve the human decision and non-goal?

If any answer is no, move the sentence to non-claims or remove it.
