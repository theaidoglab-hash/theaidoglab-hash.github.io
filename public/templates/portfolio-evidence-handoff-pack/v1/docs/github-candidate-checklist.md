# Git hosting candidate checklist

Repository candidate status: NOT_REVIEWED

Use this before asking an owner to consider whether the project could become a GitHub candidate. This is a review checklist, not a request to create or publish a repository.

## Evidence completeness

- [ ] Project brief names one decision, one human review point, and an explicit non-goal.
- [ ] Source and data receipt distinguishes fixture, public, licensed, and owner-provided material.
- [ ] Local run receipt states either NOT_RUN or an observed bounded local result.
- [ ] Claims are traceable to a receipt, fixed case, or review record.
- [ ] Non-claims rule out unsupported business, security, deployment, and production assertions.
- [ ] A stop or rollback route is visible.

## Safety and rights

- [ ] No credential, private prompt, internal URL, personal data, employer material, customer material, or confidential screenshot is included.
- [ ] Source terms and attribution needs are recorded.
- [ ] The licence decision is still accurate for the proposed sharing scope.
- [ ] Generated outputs and traces have the same privacy review as source files.
- [ ] No invented repository URL, organisation name, customer, employer, or outcome has been added.

## Owner review

- [ ] An appropriate reviewer can identify the project boundary and evidence state.
- [ ] The reviewer decision record is complete.
- [ ] The next step is explicit: retain locally, request changes, or seek a separate sharing decision.
- [ ] No public repository, release, deployment, external connection, or charge is implied by this checklist.

## Candidate conclusion

- Current candidate status: NOT_REVIEWED
- Evidence gap still open: Not recorded.
- Owner or reviewer role: Not recorded.
- Next safe action: Retain locally until an owner reviews the evidence.

A completed checklist can make a project structurally ready for owner review. It never makes a project public by itself.
